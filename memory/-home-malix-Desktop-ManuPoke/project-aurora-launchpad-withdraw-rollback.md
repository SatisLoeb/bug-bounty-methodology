**PRIMARY LEAD (HIGH→CRITICAL, un-PoC'd yet):** `contract/src/withdraw.rs` `finish_ft_withdraw`/`finish_mt_withdraw` → `rollback_investments` (L168-178) does ABSOLUTE overwrite `self.total_deposited = snapshot; self.total_sold_tokens = snapshot` captured at L47 at withdraw-init. NEAR async window is multi-block; any other account's deposit/withdraw in that window is CLOBBERED back to the stale snapshot → global aggregates desync from Σ investments. In PriceDiscovery, allocation = weight·sale_amount/total_sold_tokens, so a deflated total_sold_tokens over-allocates EVERY holder → insolvency/theft. Reachable: PriceDiscovery-Ongoing withdraw allowed with intents=Some, refund_if_fails FORCED true → attacker's failing intent → Ok(0) → rollback. claim.rs/deposit refund are delta-based (safe); bug is specific to withdraw's global snapshot-restore.

**PROVEN with executed artifact (2026-07-19):** deterministic near-sdk unit test `contract/src/tests/desync.rs::withdraw_rollback_clobbers_global_aggregates` PASSES — replays Alice deposit→withdraw(sync)→Bob deposit-in-window→Alice failed-callback(finish_ft_withdraw with Err→rollback), asserts total_deposited clobbered to 100 while Σinvestments=200 (desync) and alloc_alice+alloc_bob=2000 > sale_amount 1000 (insolvency). Warning-clean, ~0.5s. Key trick: `Some(vec![])` passes the PriceDiscovery+Ongoing `intents.is_some()` gate without building a MultiPayload; `finish_ft_withdraw` is pub (#[private]=predecessor check only) so callable directly with `&Err(PromiseError::Failed)` + `testing_env!(...,vec![PromiseResult::Failed])`.
