**FC01 (the case study to remember): technically-perfect, dead-on-recevability.** app.stakewise.io reads `SW_{rpc,subgraph,backend}Overrides` cookies with zero validation (`getOverride`, module 7248) and takes the deposit `to`/approve-spender VERBATIM from the subgraph with no allowlist; the `validateVault` guard reads over the same override-controlled endpoints (circular). PROVEN on mainnet (tx `0xa63c…818b5`, deposit to `0x…dEaD`, I re-verified via `cast`). But **DEAD**: the only cookie-plant delivery is `ipfs.stakewise.io` (open Kubo path gateway, OOS host) + requires the victim to click an attacker-distributed link = the program-excluded **social engineering against customers**. TWO independent walls (OOS delivery + SE). Operator caught the SE wall that I MISSED when hardening the report — see [[feedback-absorbable-findings-die-regardless-of-quality]], [[feedback-oos-bullet-describing-your-finding-is-its-tombstone]], [[feedback-reachability-is-kill-gate-not-severity-modifier]]. **Lesson: run the recevability gate (scope + OOS-absorbability + SE) BEFORE hardening/writing any report, not after.**

**The fan-out (rescue hunt) — 8 lanes, all executed-NULL:** A1 postMessage source-gated+response-only (Safe SDK can't inject a tx); A2 no SRI-poisonable script / SW has no fetch handler / no remote-config / no cache-poison; A5 no non-SE cookie-toss (app auto-loads ZERO `*.stakewise.io` siblings; only ipfs serves attacker-HTML-on-origin=OOS+SE); A6/me no dangling takeover on any data-path host (all Cloudflare-direct); A3 all html-sinks FilterXSS/React-escaped + proto-poll guarded + latent raw intl-Message sink has zero dynamic feeders (verified); A4 tx fields all wallet-bound/hardcoded/subgraph-bound + flagship HARDCODED (not APY-picked, so attacker vault can't auto-default); A7 api has no money mutation + claims merkle-root-protected recipient=wallet + **app doesn't even consume api.stakewise.io** (grep=0); A8 no funds-authorizing server session + no CSRF-with-impact. FC01 impact-extension (A4): same subgraph poison also freezes claim/exit (Loss+Freeze), same dead delivery.

**Structural lesson (reinforces [[pyth-staking-web-immunefi-null]] and the depth-vs-ore rule):** a single-asset Web&App scope over a **static wallet-dApp with no backend and no funds-authorizing session** is low-EV by construction — the only web→funds path is data-poisoning the tx-target, and if there's no in-scope non-SE writer for that data, there is no submittable finding. The real ore (api/oracle/subgraph/off-chain-signer) is all OOS on a single-asset scope. RE-SOURCE to a target WITH an in-scope backend/off-chain seam.
