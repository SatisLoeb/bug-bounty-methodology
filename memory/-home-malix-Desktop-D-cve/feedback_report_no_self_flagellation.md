Never write self-flagellating or deferential-toned language in security reports (Immunefi/H1/Cantina writeups, findings docs), even when report-nerve's/chill's mechanical closing-gate grep (`sorry|apolog|my fault|my bad|careless|I was wrong|overstated`) comes back clean.

**Why:** the user corrected this directly after two of my finished, grep-clean reports still carried deferential closings the grep doesn't catch — phrases like "if you'd rather I build and run that, say the word, happy to put the time in" and "I'd rather the program call that one, I'm not confident enough in how they weigh X against Y to pick a side." Neither matches a banned word, but both read as apologetic/uncertain-of-self rather than as a confident researcher stating a fact or a bounded limitation. This matches report-nerve's own "RN-1 hardening" note that grep-clean is necessary but not sufficient, and that a semantic read of self-flagellation/severity-concession/unverified-path is the real gate — the user's correction confirms that semantic read has to be applied even on non-listed phrasings, not just the literal banned list.

**How to apply:** after running the mechanical closing-gate greps on any drafted report, do an additional pass specifically hunting for deferential/self-effacing register: "say the word", "happy to", "I'd rather [you/the program] decide", "not confident enough", "if you'd rather", "up to you", "your call", "let me know if". Rewrite these into plain, confident, factual statements.

**Second, sharper round of the same feedback:** the user then flagged a bigger instance — a Severity section that pre-emptively downgraded a finding from High to "Low, possibly Medium" in the INITIAL report body, unprompted, before any triager pushed back. Quote: "ça c'est de l'auto-flagélation on se bat pour le high" (fight for the High). This extends report-nerve's Rule 2 ("no unsolicited severity concession") — written in the skill as post-submission-only — to the INITIAL report too: don't do the triager's downgrade work for them pre-emptively. Argue the strongest true case for the severity the mechanism actually supports, address the downgrade clauses by making the best counter-argument (not by capitulating to the first plausible-sounding one), and let the triager contest it if they disagree. On rewrite, the counter-argument turned out to be stronger and more precise than the concession had been: e.g. a program's "node-local configuration divergence" downgrade clause doesn't actually cover a bug that forks even a fully homogeneous, identically-configured validator set via pure per-node timing noise — that's a materially different and sharper claim than the vague "I don't know how many chains run this, might be Low" hedge it replaced. Lesson: self-downgrading is often not just bad tone, it's frequently a WEAKER, less-examined argument than the one available — check whether the "honest" concession is actually the best-supported conclusion or just the path of least resistance before writing it down.

This does NOT mean removing genuinely honest severity bounding or epistemic hedges on real inferences (decentra principle #2, chill P3/P4 both still require those where the evidence really doesn't support more) — the fix is: never concede unprompted, always make the strongest supportable case first, and reserve hedges for things truly unresolved after that case is made (e.g. "how many real chains run this in production" is a legitimate open fact-gap to name plainly, not a reason to soften the impact classification itself). Applies to every report produced under report-nerve/chill/decentra/immuformat, not just Immunefi ones.
