# CLAUDE Rules — Infrastructure / Cross-chain / Supply Chain

Load on-demand when target involves cross-chain messaging, proxy upgrade chains, RPC nodes, keeper/bot wallets, or supply-chain attack surfaces.

23. **Cross-chain messaging: validate source chain AND sender address** — The #1 cross-chain integration bug is accepting messages with only partial source validation (chain ID but not sender, or vice versa). **Auto-trigger**: grep for `lzReceive|AxelarExecutable|ccipReceive|parseAndVerifyVM|IMailbox` in Solidity. If found, §3.5 is MANDATORY. Check expressExecute has same validation as normal path. CrossCurve $3M: Axelar expressExecute lacked adequate source validation.

24. **Proxy upgrade chain: trace the FULL governance chain** — Don't stop at "admin = Safe multisig". Trace from the EOA/key that can ultimately trigger an upgrade through every intermediate contract. `EOA → Safe → Timelock → ProxyAdmin → Proxy → Implementation`. The weakest link anywhere in this chain is the effective security level. Bybit $1.4B: the weak link was the UI layer, not the on-chain contracts. Use `cast storage` for EIP-1967 slots + `cast call` for getThreshold/getMinDelay/owner at each level.

25. **Supply chain dependency audit for DeFi** — Go beyond `npm audit`. Check for: install scripts with network/wallet access, typosquats on crypto packages, maintainer changes on auth/wallet dependencies, obfuscated code in non-build packages, process.env harvesting. **Auto-trigger**: any target with a web frontend or JS build. Bybit $1.4B was ultimately a supply chain attack. npm chalk/debug Sep 2025 compromised 2B+ weekly downloads.

26. **RPC node namespace exposure** — When a protocol runs its own RPC nodes or proxies, check if txpool/debug/admin/personal JSON-RPC namespaces are exposed. `txpool_content` = mempool leak. `admin_peers`/`personal_listAccounts` = CRITICAL node takeover. `debug_traceTransaction` = state extraction. `debug_storageRangeAt` = storage enumeration without knowing slot keys (different from `eth_getStorageAt` which needs exact slot hash -- this is directory listing vs file read). **Hunt procedure (5 min per target):** (1) Find the RPC backend URL from JS bundles -- grep for `web3`, `jsonrpc`, `eth_`, `provider`, `rpc` in all chunks. (2) Check if the endpoint issues free bearer tokens -- many proxies have a `GET /auth/token` that returns JWT with zero credentials for anonymous frontend users. (3) Test namespace exposure: `txpool_status`, `txpool_content`, `debug_traceTransaction` with a real recent tx hash, `debug_storageRangeAt` against a known contract, `admin_peers`, `personal_listAccounts`. (4) If `txpool` exposed, immediately check `eth_sendRawTransaction` -- the combination of mempool observation + transaction submission on the same endpoint is the kill shot. No legitimate public RPC provider (Infura, Alchemy, QuickNode, Chainstack) exposes `txpool_content` on free/anonymous tiers. (5) Sweep all chain IDs the protocol supports (1, 56, 137, 42161, 10, 8453, 43114, etc.). (6) Check for credential leaks in error responses -- call with malformed params and read the full error body for leaked RPC URLs with auth tokens (Request Finance pattern: `persistTransaction` error leaked full QuikNode URL with token). **Internal consistency argument:** if `admin` is blocked but `txpool` is not, the proxy has a method filter with a gap -- not a design choice. **Two confirmed findings from this pattern:** 1inch F01 ($5K-$50K HackenProof, proxy open namespace, 5 chains) and Request Finance RF2-C01 (QuikNode credential in error response, txpool+debug on Gnosis).

28. **Keeper/bot wallet audit** — Identify keeper wallets (who calls harvest/rebalance/liquidate). Check: excess funds (theft target), unlimited token approvals (compromised key = instant drain), same key on all chains (single compromise = multi-chain impact). Found via contract events + config endpoints.
