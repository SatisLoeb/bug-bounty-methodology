# Infrastructure push — 2026-04-24 (scaling batch)

Production infra to address fragmentation + scaling fragilities identified
in workflow audit. Shipped in one session, auto mode. All scripts executable
and smoke-tested.

## New scripts

| Script | Location | Purpose |
|---|---|---|
| `ai-bot-check.sh` | `~/arsenal/audit-lifecycle/bin/` | Detect V12/Zellic/Olympix/Cantina AI auditor bots on target repos. Returns exit 1 if bot detected (→ deprioritize V12-covered classes: access control, input validation, reentrancy, unchecked arithmetic; prioritize logic/economic/crypto/cross-chain). Integrated into `on-finding.sh` stage 1 as advisory. |
| `archive-stale.sh` | `~/arsenal/audit-lifecycle/bin/` | Force decisions on stale Waiting Triage (≥30d no-response + ≥2 relances). Respects `disclosure_deadline` field: deadlines ≤14d trigger escalation path instead of archive. Interactive (e/E/A/s/q) or `--json` for dashboard integration. |
| `dashboard.sh` | `~/arsenal/audit-lifecycle/bin/` | Daily digest: WIP status vs caps (3 active / 2 ready), stale + urgent deadlines, relances due, findings-state.sh output, last 7d wins, today's action items. `--short` for violation-only, `--markdown` for piping to email/file. |
| `time-to-outcome.py` | `~/arsenal/tools/` | Reads OUTCOMES.jsonl, groups by finding class (auth-bypass-web, sc-fund-theft, crypto-signature, oracle-manipulation, bridge-cross-chain, etc.), outputs per-class median/p90 days-to-accepted, acceptance rate, avg reward, total paid. Enables ROI-based class prioritization. |
| `web-check-matrix.sh` | `~/arsenal/tools/` | Web/API analog of `check-matrix.py`. Discovers endpoints from OpenAPI specs, Express/Flask/FastAPI/Next.js routes. Builds endpoint × protection matrix (auth, CSRF, rate limit, re-auth, Origin, Content-Type). Groups by path prefix + verb group, flags inconsistencies (same-group endpoints missing protections siblings have). Mechanizes rules #29, #30. |
| `timebox-check.sh` | `~/arsenal/audit-lifecycle/bin/` | Mechanizes 8h rule vs L1 exception. Computes LOC + subsystem count. Thresholds: LOC ≥30K AND subsystems ≥4 → L1_EXCEPTION_ELIGIBLE; LOC ≥100K → L1_EXCEPTION_MANDATORY. Calibrated on Monad BFT (184K LOC / 52 subs) and Monad exec (170K / 5 subs) — both correctly flagged as L1. Integrated into `init-target.sh` if source present. |

## New doc

- `WIP-LIMITS.md` — Kanban discipline: Active=3, Ready=2, Waiting∞. Violation responses. Transition rules.

## Integrations

- `on-finding.sh` stage 1 — runs `ai-bot-check.sh` if `.target-repo` file exists in workspace. Advisory warning, does not block.
- `init-target.sh` — runs `timebox-check.sh` on detected source subtree, writes `.timebox-verdict` to workspace.
- `dashboard.sh` — pulls `archive-stale.sh --json`, `findings-state.sh`, OUTCOMES.jsonl last 7d, memory project files for WIP counts.

## How to use (daily)

```bash
# Morning
~/arsenal/audit-lifecycle/bin/dashboard.sh

# If stale projects flagged
~/arsenal/audit-lifecycle/bin/archive-stale.sh      # interactive forced decision

# Before audit engagement
TARGET_HINTS="solidity defi" \
  ~/arsenal/audit-lifecycle/bin/init-target.sh <target>
# → emits ROUTING.md + .timebox-verdict (STANDARD_8H vs L1_EXCEPTION)

# Before SC kill gate (automatic via on-finding stage 1)
# ai-bot-check runs; check .lifecycle-status for "ai-bot-check:<ts>:BOT_DETECTED"

# Weekly ROI review
python3 ~/arsenal/tools/time-to-outcome.py --since 30

# Web/API target surface scan
~/arsenal/tools/web-check-matrix.sh /path/to/target-repo --output matrix.md
```

## Calibration results (empirical)

| Target | LOC | Subsystems | Verdict |
|---|---|---|---|
| monad-audit/monad-bft | 184,873 | 52 | L1_EXCEPTION_MANDATORY |
| monad-audit/monad | 170,509 | 5 | L1_EXCEPTION_MANDATORY |
| tron-recon (notes only) | 491 | 0 | STANDARD_8H |

Thresholds validated: both Monad targets where the #167 consensus starvation
finding lived are correctly above the L1 threshold. tron-recon (recon notes,
not java-tron source) correctly flags STANDARD. If you clone real java-tron
(~500K LOC, 10+ subsystems), it should trigger L1_EXCEPTION_MANDATORY.

Adjust constants in `timebox-check.sh` if future targets suggest refinement.

## Not implemented (intentional scope)

- Hook on-accepted → pattern extraction (manual is fine at current volume)
- Background parallel agents (architecture trap per earlier discussion —
  cognitive bandwidth is the bottleneck, not CPU)
- Preemptive expand-surface tool construction (build when actively ramping)

## Known gaps (for next iteration)

- `dashboard.sh` WIP counter depends on MEMORY.md section headers staying
  consistent (`## Active`, `## Ready to Submit`, `## Waiting Triage`). If
  memory gets reorganized, update `count_memory_section` regex.
- `web-check-matrix.sh` middleware detection is regex-based. Miss cases:
  middlewares applied via `router.use()` at file level (applies to all routes
  below). Future: parse AST for Express, or add explicit middleware-applies-to
  annotation convention.
- `time-to-outcome.py` class detection uses keyword heuristics. Explicit
  `class` field in OUTCOMES.jsonl records overrides this — prefer setting it
  on submit for accurate grouping.
- `archive-stale.sh` disclosure_deadline extraction reads freeform text first,
  falls back to `disclosure_deadline: YYYY-MM-DD` frontmatter. Adopt the
  frontmatter format in new project files for reliability.
